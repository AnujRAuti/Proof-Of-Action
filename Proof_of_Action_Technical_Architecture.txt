============================================================
1. PROJECT OVERVIEW
============================================================

Proof-of-Action (PoA), technically called the Evidence Integrity &
Intelligence Layer (EIIL), is an API-first platform that audits
existing field evidence.

The system does NOT claim to prove that physical work happened.
Instead, it evaluates whether submitted evidence is:

- Spatially consistent
- Temporally consistent
- Visually consistent
- Complete
- Relevant to the claim
- Duplicated or recycled
- Potentially manipulated
- Inconsistent with other evidence
- Suspicious when compared across projects

The output is an Evidence Integrity Score, Risk Score, anomaly
explanations, and a recommended human-review action.

Core positioning:
"We don't collect more evidence; we make existing evidence trustworthy."

3. PHOTO ANALYSIS FLOW
============================================================

Example claim:

"100m road resurfacing completed."

Uploaded evidence:
road_after.jpg

STEP 1 - INGESTION
The backend receives the evidence and associates it with:
- Project
- Activity
- Claim
- Uploader

STEP 2 - FILE VALIDATION
Check:
- File format
- MIME type
- File size
- Corruption
- Required metadata
- Duplicate upload

STEP 3 - SHA-256
Generate a cryptographic hash for the received file.

Important:
SHA-256 proves that the received file has not changed after
ingestion. It does NOT prove that the original image is genuine.

STEP 4 - METADATA
Extract:
- GPS latitude
- GPS longitude
- GPS accuracy
- Capture time
- Timezone
- Camera manufacturer
- Camera model
- Orientation
- Software metadata
- Image dimensions

STEP 5 - GEO ANALYSIS
Check:
- Is the image inside the project geofence?
- How far is it from the registered location?
- Is GPS accuracy reasonable?
- Are multiple images spatially consistent?

STEP 6 - TEMPORAL ANALYSIS
Check:
- Is the timestamp inside the project/activity period?
- Is the sequence logical?
- Are there duplicate timestamps?
- Is there impossible travel?

STEP 7 - DUPLICATE ANALYSIS
Three useful layers:

A. SHA-256
Exact duplicate detection.

B. Perceptual hashing (pHash)
Detects:
- Resized images
- Compressed images
- Slightly modified images
- Minor crops

C. Image embeddings
Detects semantically/visually similar historical evidence.

STEP 8 - VISION ANALYSIS
Possible tasks:
- Object detection
- Image quality analysis
- Scene classification
- Image similarity
- Before/after change detection

STEP 9 - CLAIM MATCHING
Compare the claim with the visible evidence.

Example:
Claim: "10 solar street lights installed."

Expected:
- Poles
- Lights
- Installation context
- Appropriate location
- Completion evidence

STEP 10 - EVIDENCE GRAPH
Connect:
Claim
Photo
GPS
Time
Vision results
Historical matches
Other projects
Documents

STEP 11 - FUSION ENGINE
Combine all independent signals.

Example:

GPS consistency          94
Temporal consistency     91
Duplicate risk            2
Visual consistency       88
Metadata integrity       83
Claim consistency        86
Completeness            100

STEP 12 - OUTPUT

Evidence Integrity: 89/100
Risk: LOW

OR, if multiple anomalies exist:

Risk: HIGH

Why flagged:
1. 94.7% visual similarity with previous evidence
2. GPS differs from registered site
3. Timestamp conflicts with activity timeline
4. Claim is weakly supported

Recommended action:
Manual / field verification

- CONTRADICTS
- SIMILAR_TO

- CAPTURED_AT

============================================================
6. FUSION ENGINE
============================================================

No single detector should make the final decision.

Possible signals:

- GPS consistency
- Temporal consistency
- Duplicate risk
- Authenticity/manipulation risk
- Visual consistency
- Claim consistency
- Completeness
- Metadata integrity

Potential configurable MVP weights:

GPS                  15%
Temporal             10%
Duplicate            20%
Authenticity         15%
Visual               20%
Claim consistency    15%
Completeness          5%

Important:
Weights should be validated for the selected domain.

Integrity and Risk are separate concepts.

INTEGRITY:
How internally consistent is the evidence?

RISK:
How much attention should the evidence receive?

Example:

Integrity: 76/100
Risk: HIGH

Low evidence quality is not automatically fraud.

7. AI / ML COMPONENTS
============================================================

A. IMAGE EMBEDDING MODEL

Pipeline:

Image
  ->
Embedding Model
  ->
Vector
  ->
pgvector
  ->
Nearest-neighbor search

Purpose:
Find visually/semantically similar evidence across historical data.

B. PERCEPTUAL HASHING

Pipeline:

Image
  ->
pHash
  ->
Similarity
  ->
Near-duplicate detection

Purpose:
Detect resized, compressed, cropped or slightly modified versions.

C. OBJECT DETECTION

Example:
Claim = "Solar street lights installed"

Model detects:
- Pole
- Street light
- Installation context

D. BEFORE / AFTER COMPARISON

BEFORE
  +
AFTER
  ->
Comparison
  ->
Changed regions
  ->
Change confidence

Possible analysis:
- Common scene
- Relevant regions
- Objects
- Structural changes
- Textures
- Damage state
- Construction stage

E. IMAGE QUALITY

Detect:
- Blur
- Darkness
- Overexposure
- Obstruction
- Low resolution
- Extreme angle
- Irrelevant framing

F. LLM

Good uses:
- Claim extraction
- Report summarization
- Reviewer assistance
- Natural-language investigation
- Explanation generation

Bad use:
Do NOT simply ask an LLM:
"Is this photograph real?"

The core verification engine should rely on deterministic
rules and vision-based signals.

16. IMPORTANT TECHNICAL RULES
============================================================

RULE 1:
Similarity does NOT automatically mean fraud.

Two legitimate projects can photograph the same building.

RULE 2:
GPS alone is NOT proof.

GPS should be treated as one evidence signal.

RULE 3:
AI output must include confidence.

Every finding should contain:
- Finding
- Confidence
- Severity
- Supporting evidence

RULE 4:
Model versions must be stored.

Preserve:
- Model name
- Model version
- Weights hash
- Configuration
- Thresholds
- Analysis timestamp

RULE 5:
Every AI decision must be reproducible.

Preserve:
- Input
- Metadata
- Model
- Model version
- Configuration
- Thresholds
- Matches
- Rules
- Output

RULE 6:
If AI analysis fails, do not delete evidence.

Store it, retry analysis, and send repeated failures to manual review.

19. FINAL PRODUCT POSITIONING
============================================================

Problem:
Large-scale field programs generate huge volumes of evidence,
but manually verifying whether evidence is genuine, consistent,
complete and relevant does not scale.

Solution:
An AI-assisted evidence intelligence layer that correlates:
- Visual evidence
- Metadata
- GPS
- Time
- Claims
- Historical submissions
- Project relationships

to generate explainable integrity and risk signals.

Innovation:
Treat evidence as a connected, auditable graph rather than
isolated photographs.

Human Safety:
AI prioritizes and explains.
Humans make consequential decisions.

Do NOT claim:
- 100% fraud detection
- AI proves government work
- Elimination of field officers
- An unfoolable detector
- Every image can be authenticated

Use:
"We detect anomalies and prioritize evidence for human verification."
